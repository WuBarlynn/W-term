# 同步密钥轮换

更新：2026-10-08。下文记录 0.1.30 起的本机轮换核心；0.1.31 已验证 GitHub 发布，0.1.38 增加已绑定设备的手动[新密钥接入](SYNC_KEY_ADOPTION.md)及界面。0.1.39 (40) 已接入本机发起、恢复码核验、发布/恢复与安全丢弃界面。

## 两阶段轮换

1. `crypto::rotation::begin` 要求已有一次确认成功的普通同步、没有待处理批次/发件箱，且本机同步检查点与已确认基线一致。生成新的随机数据密钥、新编号、由指定同步口令包装的信封及新恢复码。
2. 在一个 SQLCipher 事务中创建轮换批次和候选密钥，活动密钥保持不变。候选只重加密上次已确认的同步快照；尚未同步的业务编辑留在本机，之后通过普通同步捕获。
3. 创建返回新恢复码一次。`confirm_recovery` 需要用它实际解开候选信封，核对后才允许生成上传内容。核心能核验码正确，不能证明用户已离线保存；界面要求勾选已离线保存并重新输入新恢复码。恢复码不存入候选记录。
4. `outbox::stage` 为轮换批次选择候选密钥，生成并持久化密文与新信封；后续重试使用相同字节。旧活动密钥不能解开新包。
5. 将密文和信封放在同一远端提交，读回并核对内容。只有 `outbox::acknowledge_published` 的事务成功后，才保存旧密钥、切换活动密钥、删除候选、推进检查点、清除发件箱和保存回执。

新口令仍使用既有 Argon2id 参数，快照仍使用既有 AES-GCM/HKDF 格式；此轮未新增密码算法。可以指定新口令，但核心不强制它与旧口令不同。若沿用已泄露口令，轮换数据密钥不能阻止持有该口令的人解开新信封。

## 失败和恢复

- 生成或保存失败：不改变活动密钥；候选和轮换批次共同回滚。
- 尚未核验恢复码：禁止生成上传包。若在恢复码保存前退出，可在确认未发布后取消再创建；不提供读回恢复码接口。
- 已暂存但发布结果未知：保留候选、旧活动密钥和原密文，等待核对，不自动取消或提前切换。
- 候选丢失/损坏、批次/操作版本不符、信封损坏：停止轮换上传及确认。待处理批次包含 `key_rotation` 标记，缺失候选不会退回旧密钥重加密。
- 发布确认过程中历史密钥保存、活动密钥更新、检查点或回执保存失败：整个事务回滚，仍可恢复相同候选和密文。
- 重复成功确认沿用发件箱回执逻辑；不会重复增加历史密钥或清理新的批次。
- 只有已确认远端未接受时才能取消。取消在同一事务清除候选、轮换批次和发件箱，保持活动密钥及业务记录不变。

普通状态确认和一次性 `encrypt_pending` 不接受轮换批次，必须通过持久发件箱。当前仅本机依赖发生变化时，继续发送仍受发件箱隐私检查约束；若在途发布已成功，确认仍记录真实结果。

## 历史读取和容量

`decrypt_retained` 根据密文内的密钥编号在当前密钥或本机历史密钥中选择，再执行完整认证解密。认证通过不等于可以把旧快照应用到当前保险库，也不能替代远端版本/回滚检查。

本机保留最多 16 把历史密钥，达到上限拒绝新轮换，不自动删除历史密钥。尚无清理界面或归档导出协议。新恢复码可解开新信封和其对应数据，不能据此恢复另一台设备上从未保存的旧历史密钥；恢复码不是整个密钥历史的备份。

轮换不会撤销旧仓库提交、旧备份或已下载副本。持有旧数据密钥或旧信封及其解锁凭证的人仍能读取对应旧密文。此流程不会向旧密钥持有者自动发布新密钥；其他已绑定设备需要通过换钥接入流程使用新口令或新恢复码。

## 本机格式兼容

- SQLCipher schema 3 不变。
- `sync_key_rotation_v1`：候选密钥、信封、上代编号、批次、操作版本和恢复码核验状态，最多 16 KiB。
- `sync_key_history_v1`：版本和旧密钥/信封列表，最多 256 KiB、16 项；校验空间、编号唯一性及信封 MAC。
- `sync_key_v1`：仍保存唯一活动密钥，格式不变。
- 待处理批次增加 `key_rotation`。旧 v1 状态缺失此字段按普通批次读取；旧版本不应参与已开始的轮换，候选格式与未知字段仍采用拒绝策略。
- 不自动修改用户保险库。现有备份导出可包含加密 metadata，但“恢复为新记录”不复制同步状态/密钥历史。

## 0.1.39 操作入口与服务层约束

1. 侧栏“GitHub 同步” → “轮换 / 恢复同步密钥”。已有待处理轮换时可重新打开；仓库设置未保存时入口禁用。
2. 首先完成一次普通同步及所有冲突处理。输入两遍至少 12 字符的新独立同步口令，确认其他设备需要重新接入，然后生成。
3. 离线保存展示一次的新恢复码，重新输入并勾选已保存，再核验。此步不发布。口令和恢复码输入提交后立即清空；核验通过后清除展示的恢复码。
4. 显式点击“发布 / 恢复轮换”。成功确认后其他设备使用新同步口令或恢复码接入，本机尚未同步的编辑继续普通同步。
5. 关闭窗口保留进度，但不保留恢复码显示；未核验又丢失恢复码时，只有未发布的候选才可勾选确认后丢弃重建。停止当前操作只中断网络等待，不丢弃候选。

生成前，服务层检查仓库身份、提交读取下限、远端版本与已确认版本相同、信封一致、认证解密快照与已确认基线相同；失败不会生成候选。读取后远端仍可能变化，发布阶段继续使用原版本检查。

核验、发布和丢弃均绑定候选批次 ID，旧窗口不能操作后来重新创建的轮换。状态接口不提供恢复码读回。只有没有分支更新日志，或日志证明从未发送 / 首次明确拒绝时才能丢弃；网络不明、5xx、旧日志缺字段一律保留。丢弃在同一 SQLCipher 事务清理候选、发件箱、待处理状态与发布日志，保留活动密钥、历史和业务记录；保存失败整体回滚。
