# 当前开发路线

更新：2026-10-08。本文件是后续工作的执行顺序；[原计划](../PLAN.md)保留长期功能目标，发生顺序或范围冲突时以本文件为准。技术路线保持 Flutter 自适应界面 + Rust 共享核心。

## 范围与取舍

- 先完成 macOS 和 iOS/iPadOS，再进入 Windows；Android 在全部已规划阶段完成后单独评估。
- 暂停 SFTP 新功能。保留已有文件管理、编辑及传输，只处理影响使用或数据安全的缺陷；递归下载、续传、目录对比等退出当前排期。
- 当前已有主机/文件夹管理、可复用密码与密钥、SQLCipher 保险库、备份恢复、多会话终端、主题/搜索/片段、常用 OpenSSH 配置导入。编译或模拟测试通过不代表真机验收完成。
- 当前主要缺口：GitHub 加密同步、多跳/连接代理、MFA、完整转发、恢复码及 Apple 真机稳定性。后续以完整用户流程为交付单位，避免持续扩展同一局部模块。

## 阶段 1：本轮交付边界

连接已认证主机 → 会话顶部“端口转发” → 填写目标及本地端口 → 启动 → 通过本机地址访问 → 停止或断开会话。

- 首版只绑定 `127.0.0.1`；本地端口 `0` 表示自动分配，目标端口必须为 1–65535。
- 目标地址从 SSH 服务器侧连接；监听成功并不证明目标服务可访问，连接失败在刷新列表后显示。
- 每会话最多 8 条转发，每条最多 32 个并发连接；目标通道连接超时 15 秒。
- 转发与当前会话绑定。关闭管理窗口继续转发；停止、终端退出、会话断开会释放资源。当前 iOS 后台策略会断开 SSH，因此同时停止转发。
- 本轮不保存转发规则、不自动恢复、不绑定局域网地址；远程转发和动态 SOCKS 位于阶段 3。
- 真机后台/前台、真实 OpenSSH 服务器、macOS 沙盒和长连接压力测试仍需验收。

## 阶段 2：工作的拆分

1. **数据协议先行：**盘点主机、身份、文件夹、片段的现有字段，确定稳定 ID、记录版本、删除标记、同步排除标记、导入迁移和大小限制。先实现两个临时保险库之间的导出/合并测试。
2. **加密与恢复：**独立同步密钥、认证加密封装、独立同步口令/恢复码解锁和密钥轮换；从协议层保证凭证及可导出私钥不以明文上传。复用审查过的密码库，不自行设计密码算法。
3. **GitHub 传输：**私有仓库、细粒度令牌及最小权限；令牌仅本机安全保存。先手动同步，使用远端提交版本做并发校验，禁止强制推送。账户授权或创建远端资源另行由用户提供。
4. **冲突与失败恢复：**并发改同项、编辑与删除、离线重连、网络失败和部分提交；保留双方副本并呈现来源，用户确认后解决。不能仅按时间戳静默覆盖。
5. **界面和双端验收：**同步状态、待处理冲突、恢复流程、可导出密钥/仅本机身份边界；用两份隔离数据与签名设备测试。全过程避免在日志、错误和仓库元数据中泄露秘密。

## 每次交付的固定要求

- 说明新行为、入口和限制；同步更新 [STATUS.md](STATUS.md)。
- 执行与改动对应的测试；Rust 协议改动需本机真实 SSH fixture，桥接改动需加载实际动态库验证。
- 完成 macOS 与 iOS 构建并核对版本、Rust framework、IPA 完整性；遇到环境阻断明确记录，不能将旧包当作新版本。
- 自动化、构建、人工真机验收分开记录。Apple V1.0 验收前不开始 Windows，不用自动化结果代替四周日用。
