# GitHub 加密传输核心

更新：2026-10-07，0.1.32 (33)。Rust `sync::github` 已接入 Flutter 手动同步流程，已用本地 HTTP 服务测试。账户配置和令牌 SQLCipher 保存已实现，**真实 GitHub 仓库验收尚未完成。**使用流程见 [SYNC_SETUP.md](SYNC_SETUP.md)。不自动创建仓库、分支、令牌或后台任务。

## 首版范围

- 仅 GitHub.com 固定 API 地址 `https://api.github.com`，reqwest 0.12.28 + rustls；API 版本固定为 `2026-03-10`。
- 用户指定已有私有仓库和已存在的线性分支，建议使用专用同步分支。仓库需已初始化，空仓库/缺失分支暂拒绝。
- 仓库地址只能由经过验证的 owner/repo/branch 构造，不接受任意 URL 或响应中的下载 URL。分支首版只接受字母、数字、横线、下划线和斜线。
- 发起发布需仓库元数据显示私有、未归档、有 push 权限。设置界面保存指定私有仓库的令牌，使用 Contents 读写权限；由编排层从本机 SQLCipher 读取后传入客户端，无明文令牌读取接口。
- 两个根目录文件：`wterm-packet.json`（快照密文）、`wterm-key.json`（密钥信封）。提交说明固定，不包含主机名称、密码或恢复码。沿用原 root tree，保留其他文件；不创建或更改 Actions 工作流。

## 一次发布

1. 读取或创建已持久化发件箱；恢复已有尝试时只读取用于核对的字节，此时不因为本机之后的隐私依赖变化而丢失已发布结果。
2. 核对仓库真实数字 ID、owner/repo 和分支，与 SQLCipher 中的永久目标绑定一致。读取分支 head。已有同步时 head 必须等于批次基线；首次同步要求两份同步文件都不存在。
3. 在任何网络写入前持久化发布尝试：目标绑定、批次/操作版本、Git 父提交、待发布提交号（初始显式 null）。重新检查仅本机规则，再创建两个 blob、包含两份文件的新 tree 和单父 commit。
4. 将返回的新提交号持久化，成功后才允许推进分支。保存失败可能留下不可达加密 Git 对象，但不会由本实现更新分支；重试可以重新创建对象。
5. 再次读取分支头，并再次检查本机隐私范围。分支仍为原父提交时，以 `force: false` 更新；若已包含自己的提交，则只核对结果，不重复推送。其他变化停止，保留批次。
6. 读取更新后的 head，核实候选提交仍在其祖先链中。从候选提交的同一 tree 读取两份文件，验证 blob Git 对象摘要、父提交和原始发件箱逐字节一致。
7. 同一 SQLCipher 事务更新同步检查点、必要时激活候选密钥、清理发件箱、写确认回执并删除 GitHub 发布尝试。任一步失败整体回滚。

首次同步的加密包逻辑 parent 仍为 null，实际 Git commit 的父版本是仓库已有 head；这两个概念分别由批次和发布日志保存、检查，不混用。

## 中断、竞争与回滚边界

- HTTP 失败、限流、超时或连接中断不自动重试网络写操作，不确认也不删除待处理数据。一次请求最多 30 秒、连接最多 10 秒；一次 fetch/publish 操作上限 120 秒，取消 future 同样保留已持久化状态。
- 分支更新成功但响应丢失：重试查分支历史，确认已记录的提交在分支上并读回原字节后再确认本机。不依赖重新加密或重新生成提交来猜测成功。
- 候选提交之后已有其他提交：可以确认自己的祖先提交，检查点记自己的提交号，不误认最新 head 是自己的结果。下一次读取继续处理后续变化。
- 竞争产生的同父不同子提交不能通过快进更新覆盖；遇到 `409/422` 保留所有本机待处理状态。
- REST `force: false` **不是携带 expected old SHA 的严格原子 CAS**。发布前的 head 复核和快进约束能保护正常并发追加，但无法消除管理员在检查与更新间强制回退分支的竞态。不承诺在外部强推、删除重建或仓库权限同时变更下实现完整防回滚；真实上线前仍需结合分支保护和版本策略验收。
- 祖先检查最多遍历 64 个线性提交；遇到合并提交、环、不足以证明关系或超过上限均停止。不是任意 Git 历史遍历器。
- 有发布尝试时，普通发件箱确认和直接取消被阻止，必须先完成网络结果核对。首版尚无竞争后的自动取消/重新合并入口，也不自动解除仓库绑定。不要通过删除 metadata 强行恢复。

## 读取与错误保护

`fetch(pinned)` 固定一次分支 head，从该不可变提交获取两份文件。传入已确认版本时，必须证明其仍在分支祖先链中；认证解密和合并由 `sync::service` 编排层处理。远端密钥信封改变时停止，其他设备换钥接入尚待实现。

拒绝半套文件、符号链接/非普通文件、重复路径、截断 tree、未知 Git 编号、错误 blob 大小/摘要。Git blob 的 SHA-1 仅验证 Git 对象一致性，敏感数据真实性仍由已有 AES-GCM 认证负责。元数据响应最多 1 MiB、tree 根目录最多 1000 条，首次同步需额外预留两条位置；密文 24 MiB、信封 16 KiB，HTTP 流式读取同时检查 Content-Length 和实际累计大小。

不跟随重定向，TLS 默认验证开启，不将敏感令牌写入 URL、错误、日志或本机发布记录。Authorization header 标记为 sensitive；第三方 HTTP 库的内存副本不保证全部清零。错误只给出本机说明及 HTTP 状态，不返回服务端正文，避免服务器回显凭证。

## 存储

沿用 SQLCipher schema 3：

- `sync_github_target_v1`：创建/接入空间时绑定的仓库 ID、owner/repo、分支。
- `sync_github_attempt_v1`：未完成发布及其 Git 父版本/候选提交号。

每项最多 8 KiB，版本、必需字段、目标和批次不匹配时停止；提交号更新使用本机事务比较，不能让竞争调用覆盖另一次尝试。当前应用的“恢复为新记录”不复制这些同步元数据。
