# 同步加密与恢复（草案 v1）

更新：2026-10-05，0.1.28 (29)。`rust/src/sync/crypto.rs` 为 Rust 内部核心，尚无 Flutter 同步入口、GitHub 传输或真实多设备验收。格式在网络功能发布前仍可能调整。

## 密钥层次

- 为每个同步空间生成独立的 256 位随机数据密钥和 UUID 密钥编号，不使用本机保险库密码直接加密同步数据。
- 独立同步口令经 Argon2id v19 派生包装密钥：64 MiB、3 次迭代、并行度 1、32 字节输出、随机 16 字节盐。口令至少 12 个字符、最多 1024 字节，不截断或规范化。
- 恢复码含独立随机 256 位包装密钥，前缀 `WT1`、八组 8 位十六进制及 8 位校验码；校验码是带固定域标识 SHA-256 的前 4 字节，只用于发现输错。支持大小写及首尾空白。
- 同步口令和恢复码分别包装同一数据密钥。任一路径均可恢复；恢复时还需要对应密钥信封。丢失口令和恢复码且无已解锁设备时，当前核心不能恢复密钥。
- 恢复码只由创建接口返回，不写入同步包、本机密钥记录或日志。拿到恢复码及密钥信封即可解密，应由后续界面提供离线保存及确认流程。

## 密钥信封

`KeyEnvelope` 包含固定版本/算法/KDF 标识、空间及密钥 UUID、口令盐、口令包装槽、恢复码包装槽和整体 HMAC-SHA256。包装槽使用 AES-256-GCM；附加认证数据为 JSON 元组 `['wterm-sync-key-wrap-v1', header, purpose]`，其中 purpose 区分 password/recovery。

整体 MAC 密钥由数据密钥派生，固定 32 字节零盐，HKDF info 为 `wterm-sync-v1` 与 `key-envelope-mac` 拼接。MAC 覆盖完整的包装结构；成功解开一个槽后仍校验整体 MAC，另一个槽被替换也会拒绝。MAC 不证明某个具体设备身份；持有共享密钥的设备均能生成有效内容。

格式和大小先检查，再运行 KDF。只接受固定 KDF 配置，不能由外部文件指定超大内存/迭代参数；信封最多 16 KiB。口令派生在进程内串行，显式分配并清零 Argon2 工作内存。真机耗时、峰值内存和移动端取消体验待测。

## 快照密文

`Packet` 包含 `header` 和 `sealed`：

- header 字段依序为 `version`, `suite`, `space`, `key_id`, `batch_id`, `parent`；父版本必须显式存在，可为 null，否则为 40/64 位十六进制提交值。
- 密文上限 24 MiB；明文快照沿用 16 MiB 限制。认证通过后才能解析快照，快照空间必须匹配密钥空间。
- 每次封装生成新的随机 32 字节盐和 12 字节 nonce。HKDF-SHA256 从数据密钥派生 32 字节 AES 密钥，info 为 UTF-8 `wterm-sync-v1` 直接拼接 AAD。每次封装使用独立派生密钥，调用方不能指定盐或 nonce。
- AAD 为按 Rust 结构字段顺序序列化的 header 紧凑 JSON（无多余空格）。AES-256-GCM 使用完整 16 字节认证标签，追加在密文尾部。盐、nonce、含标签密文使用标准带填充 Base64。
- 解码时拒绝未知字段、错误版本、空间/密钥编号不符、非法长度及认证失败。JSON 输入格式可不同，但认证重新使用上述确定字段顺序；跨语言实现必须采用同一 AAD 编码。

空间/密钥/批次编号、父提交、密文大小以及仓库提交时间可见；主机地址、用户名、密码、可导出私钥等快照内容在密文内。加密不隐藏访问频率。认证有效的历史包仍然有效，**本层不提供新鲜度或防回滚保证**；后续传输必须与已固定的远端版本及待处理批次核对。

## 本机托管与批次

`install` 将数据密钥及信封存到已解锁 SQLCipher 的 `metadata.sync_key_v1`，沿用 schema 3。需要已初始化且空间相符的同步状态，存在待处理批次或已有密钥时拒绝安装，防止直接覆盖造成历史数据不可读。`load` 校验容量、版本、空间及信封 MAC。

`encrypt_pending` 读取持久化批次，并重新检查仅本机凭证依赖，输出加密候选；只需确认拉取的批次不产生上传包。相同批次重复加密会产生不同字节，0.1.29 起网络适配器应使用 [密文发件箱](SYNC_OUTBOX.md) 保存首次生成的字节，重试直接复用，不能以重新加密的字节不等判断上传失败。

当前备份导出可以包含加密 metadata，但应用的“恢复为新记录”流程不复制同步元数据，也不会开启同步。恢复码不是本机保险库密码的替代品。

自有数据密钥、派生密钥、恢复码字符串、明文缓冲和 Argon2 工作内存使用尽力清零容器；不承诺清除第三方库内部状态、所有解析副本或操作系统内存副本。未接受独立安全审计。

## 自动化与后续

新增 8 项 Rust 测试：两种解锁路径、错误凭证/空间、随机化及密文/头部篡改、整体信封认证、恢复码校验、格式与容量拒绝、SQLCipher 重开及另一保险库恢复、仅本机数据排除。

另有独立 Python `cryptography` AES-GCM/HKDF 双向互操作测试：Rust 生成包交给 Python 解密，Python 换盐/nonce 重新加密，再由 Rust 读取。只通过标准输入传递合成密钥，不使用用户数据。运行 `bash scripts/test-core.sh` 包含此测试。
