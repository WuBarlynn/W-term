# 同步核心：协议草案 1

更新：2026-10-07。状态：**已接入 GitHub 手动同步与持久冲突选择；真实 GitHub 和签名设备尚未验收**。当前为开发预览。使用入口见 [SYNC_SETUP.md](SYNC_SETUP.md)，选择与并发保护见 [SYNC_CONFLICTS.md](SYNC_CONFLICTS.md)，执行顺序见 [ROADMAP.md](ROADMAP.md)。下文记录协议和早期核心的设计。

## 协议与合并核心（0.1.26 起）

`rust/src/sync` 提供内存快照、三方合并和 SQLCipher 事务适配器。测试使用两份独立、不同路径的加密保险库；不使用用户数据库或凭证。现有本地保险库保持 schema 3，没有自动迁移或后台同步行为。

### 记录模型

- `version`：同步协议版本，目前为 1；未知版本、未知字段和重复记录均拒绝。
- `space`：同步空间 UUID，三个输入必须属于同一空间。
- `key`：类型与稳定 ID。主机、身份和片段沿用本地 ID，不像恢复备份那样生成新 ID。
- `revision`：设备 UUID 与递增计数。实际内容改变才产生新版本；不使用系统时钟决定覆盖权。计数到上限时拒绝继续生成版本。
- `value`：必填；对象/数组表示现存内容，显式 `null` 表示删除标记。字段缺失不是删除。历史删除标记保留，不在本轮做清理。
- 单个快照最多 16 MiB、32,000 条记录（含删除标记）；现存主机/身份各最多 10,000、片段最多 1,000。合并结果也校验主机/片段集合的既有 4 MiB 限制，不能因为两端各自合法就接受超限总量。

**文件夹的过渡方案：**现有保险库按路径存文件夹，没有独立文件夹 ID。本轮将文件夹树保存为固定 `folders/tree` 记录；两端同时修改文件夹树会产生整体冲突，保留双方。首次空集合不产生伪冲突，删除已有文件夹树则产生删除标记。更细的目录合并需要先设计稳定文件夹 ID 与迁移，不能声称当前已支持逐文件夹无冲突合并。

### 合并规则

输入为共同基线、本机快照、远端快照。基线必须是调用方确认双方共享的版本，不能用未被远端接收的本机状态替代。

| 情况 | 结果 |
| --- | --- |
| 两端内容相同 | 收敛为确定的内容和版本元数据 |
| 一端变化，另一端等于基线 | 接受变化，包含显式删除 |
| 两端对同一记录做不同修改 | 保留基线及双方完整记录，返回冲突 |
| 一端删除、另一端修改 | 保留修改与删除两种意图，返回冲突 |
| 基线中的记录在某端无记录也无删除标记 | 拒绝不完整输入，避免误删或复活 |
| 合并后主机指向已被另一端删除的身份 | 返回引用冲突，阻止写入 |
| 协议版本、空间或记录版本检查失败 | 整体拒绝，不改本地数据 |

任一未解决冲突都会阻止整个计划写入和生成可发布结果。本轮尚未实现用户选择、持久化冲突中心或“保留两份”的 ID/关联重映射；双方内容保留在内存计划中，原始保险库保持不变，不会静默选一端。

### 事务边界

捕获在同一个 SQLite 读取事务中完成，避免主机和凭证来自不同时间点；调用方不能已在此连接上开启事务。写入先取得 SQLite IMMEDIATE 事务并再次读取本机数据，和生成计划时的本机快照比较。不一致则要求重新合并。身份、主机、文件夹和片段一起提交；密钥格式、口令、容量或 SQL 校验失败，整个事务回滚。软件密钥在写入前解析验证。

0.1.27 起增加持久化状态模块（下节）：数据合并与检查点在同一个事务提交。未上传成功的候选不能成为共同基线；已经验证并应用的远端快照可以成为重试基线。网络发布结果不明时如何核对远端内容，仍由后续传输适配器实现，不能仅凭本轮本地事务测试宣称已解决真实 GitHub 中断恢复。

## 持久化状态与仅本机策略（0.1.27）

状态存入 SQLCipher `metadata` 的 `sync_state_v1`，总大小上限 64 MiB。保险库 schema 3 不变；尚未接入应用入口，因此不会自动为用户保险库开启同步。

保存的字段包括：同步空间、设备 UUID、递增操作版本、共同基线、本机同步快照、已观察到的远端提交版本、仅本机规则、待处理批次和最近确认回执。快照和待处理数据含敏感信息，随 SQLCipher 加密落盘，不生成独立明文文件。应用旧版的正常备份恢复流程不复制这些状态，恢复的记录仍按原逻辑获得新 ID；同步政策不会自动继承到这些新 ID。

### 批次与恢复流程

1. 初始化时生成并保存设备 ID，同一空间重复初始化保留原状态；不同空间或损坏状态均拒绝静默重置。
2. 准备批次时检查调用方的操作版本，捕获本机、应用仅本机规则，再和远端合并。有冲突时不修改数据或检查点。
3. 无冲突时，在一个 IMMEDIATE 事务中提交本地合并结果、已经验证的远端基线、待上传的精确候选和批次 UUID。数据或状态保存任一失败，整体回滚。
4. 关闭并重开数据库后可以恢复同一批次。恢复时重新检查当前凭证关联；若新的关联使待上传内容属于仅本机数据，阻止取出该批次，要求确认取消并重建。
5. 传输层应在发送前重新读取待上传批次，并验证远端并发版本。成功后用匹配批次 ID、父提交版本及新提交版本确认；只有这时才将待上传候选设为共同基线。确认不重写业务数据，因而保留用户准备批次后的新修改；同一回执重复确认是幂等操作。
6. 若候选与已读取的远端完全一致，则标记为仅拉取，可确认原远端版本，不要求创建无意义的新提交。
7. **取消批次只能在已确认远端未接受该批次后执行。**取消保留本地已合并内容和已接收的远端基线，下一次重新合并；不会用旧数据回滚用户新修改。远端结果不明时必须保留待处理状态，后续适配器需先核对远端内容。

操作版本阻止过期调用覆盖新状态；有待处理批次时不能更改政策或准备第二个批次。远端同步数据消失、相同提交版本对应不同数据、错批次回执均拒绝。当前 Rust 接口假定调用方已验证远端快照及回执内容；这不是已实现的 GitHub 并发控制或网络认证。

### 仅本机规则

- 可排除主机、身份、命令片段的稳定 ID。凭证与主机形成双向关联：主机私有时，其身份及共用身份的主机一并排除；身份私有时，所有引用主机一并排除。检查当前数据和同步历史中的关联。
- 排除记录的正文不进入共享候选；将共享候选写回本地时，保留原有私有记录。远端同 ID 的现存记录与私有规则冲突时阻止合并；远端删除标记不能删除本地私有数据。
- 从未发布的私有记录可以重新选择参与同步，并保留原 ID。已经存在于共同基线的现存记录，不能直接改为仅本机；远端撤回及历史保留说明尚未实现，不能以本地开关承诺删除远端历史。
- 文件夹树暂不支持独立的仅本机规则。排除某个主机不会自动将文件夹名称视为私有；当前文件夹集合仍按原来的整棵树模型处理。
- 这套排除规则目前仅在 Rust 核心及隔离测试中使用，尚无主机/身份编辑器开关。当前应用创建/接入时要求授权整体同步范围，逐项预览及开关仍待实现。

## 凭证与加密边界

底层完整捕获包含软件身份的密码、私钥和口令；持久化编排层在形成待上传候选时应用仅本机排除规则。它只供 Rust 内存里的同步核心处理，没有新增 Flutter 明文凭证读取、明文文件导出或网络上传接口。`encode` 生成的是待加密的明文内存缓冲，不能直接持久化或交给 GitHub。

快照和冲突类型不实现 Debug；自有记录与输出缓冲尽力清零，解析和克隆中间副本不能保证全部擦除。SQLCipher 两库测试验证落盘内容不含测试密码明文，但这不能代替同步传输的端到端加密。

手动网络流程和冲突界面已在 0.1.32–0.1.34 接入；发布读回和响应丢失恢复通过本地 HTTP 测试，仍待以下验收与增强：

1. 真实 GitHub、真实异常退出和签名设备双向同步验证，不能以本地模拟代替。
2. 将仅本机规则接入主机/身份界面，提供关联影响预览及已发布数据撤回流程；设备信任指纹、Keychain 快速解锁项和 GitHub 令牌不能进入此快照。
3. 竞争发布后的安全恢复、外部强推的回滚边界，以及其他设备换钥接入。本机轮换见 [SYNC_ROTATION.md](SYNC_ROTATION.md)，传输边界见 [SYNC_GITHUB.md](SYNC_GITHUB.md)。
4. 轮换管理、解除绑定与范围管理界面，以及 Apple 真机生命周期和长期日用验收。

## 持久化密文发件箱（0.1.29）
