# 同步冲突处理

更新：2026-10-07，0.1.34 (35)。入口：侧栏 **GitHub 同步 → 处理同步冲突**。

## 使用流程

1. 点击立即同步。双方修改同一条记录、修改与删除冲突或身份关联不一致时，停止业务合并，并把本机与远端原始版本加密保存在本机保险库。
2. 打开处理同步冲突。每项显示本机/远端摘要及变化字段；主机显示名称、地址、端口、用户名与文件夹，身份显示名称/用户名/认证方式，片段显示名称与命令长度，文件夹显示总数和部分路径。长字段会截断。
3. 为每项选择 **保留本机** 或 **保留远端**。删除版本会明确显示为 **采用本机删除 / 采用远端删除**。没有默认选择，也不会按时间自动覆盖。文件夹作为整棵树选择，首版不逐路径合并。
4. 勾选确认，再点 **应用并同步**。未选中版本会被所选版本替换，不自动创建重复记录。确认前可关闭窗口，原数据保持不变。冲突数据会保留供下次查看，尚未提交的界面选择不保存。
5. 如果选择已写入但上传失败，关闭冲突窗口并点击 **恢复待处理同步**；不会再次应用已失效的冲突选择。

密码、私钥、私钥口令与命令正文不通过冲突接口返回 Flutter；仅显示是否变化。用户可以根据来源选择版本。首版不提供明文秘密比较或“保留两个副本”。

## 身份关联

保留的主机必须能找到其身份。身份两端都存在但内容冲突时选择身份版本即可；如果某个可选主机引用了原本被自动删除的身份，会把该身份提升为待选择条目。可能受身份删除影响的主机也纳入同一选择集合。

选择“保留主机 + 删除它引用的身份”会整体拒绝，不部分写入。可改为同时保留该身份，或采用不引用它的主机版本。

## 并发与失败保护

- 本机冲突审阅记录包含随机编号、同步操作版本、完整本机快照、认证解密后的远端快照和远端提交号。存储在 SQLCipher `metadata.sync_conflict_review_v1`，最多 34 MiB。它不进入同步快照；完整加密数据库备份可能包含该记录。
- 读取界面时重新捕获本机数据；本机业务编辑或同步状态变化使旧审阅失效。重新点击立即同步会生成新审阅编号；旧窗口不能提交新列表的选择。
- 确认时重新读取远端，要求提交号与审阅一致，并重新认证解密和核对内容、仓库 ID 及密钥信封。远端有新提交时先停止，提示重新同步再选择。
- 本机写入事务再次检查审阅编号、本机快照和同步状态；所有选择必须完整、唯一且属于当前列表。解决后的版本计数大于两侧版本，身份依赖和容量检查通过后才应用。
- 合并业务数据、保存待处理批次和删除当前审阅在同一个 IMMEDIATE 事务中提交。任何一步失败整体回滚，保留双方内容及原审阅；成功后不能重复提交旧审阅。
- 发布继续使用已有加密发件箱和非强制更新流程。确认后至实际发布间仍可能出现新的远端提交，此时保留待处理批次；竞争后的可验证取消/重新合并还未完成。取消不能撤回服务器已接受的提交。
- 审阅成功应用后不单独归档未选中的版本；如需长期保留所有旧版本，应在确认前使用已有加密备份功能。

## 验证边界

新增 Rust 测试覆盖关闭重开、加密保存、秘密不出现在摘要、修改/删除、文件夹选择、身份依赖提升、无效/重复/不完整选择、过期本机快照/审阅编号、事务失败回滚和重复提交。扩展 HTTP 集成覆盖远端变更拒绝、刷新审阅、发布响应丢失及两端最终收敛。Flutter 覆盖无默认选择、逐项确认、删除标签、关闭取消、提交后待处理状态及 320px 布局；真实桥接检查新增入口。

真实 GitHub 及签名 macOS/iOS 两端验收尚未完成。下一步优先竞争恢复和换钥接入，再继续 SSH 连接能力；不扩展 SFTP。
