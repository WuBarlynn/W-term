# GitHub 手动加密同步

更新：2026-10-07，0.1.34 (35)。这是开发预览流程；本地 HTTP 模拟通过不等同于真实 GitHub 和签名设备验收。

## 入口与设置

1. 解锁保险库，在左侧选择 **GitHub 同步**；iPhone 从侧栏进入。
2. 填写 GitHub.com 私有仓库的所有者、名称、已有分支和令牌。仓库需已初始化，例如包含 README；首版不创建仓库或分支，不支持企业自建地址。令牌需要该仓库 Contents 读写权限，分支规则须允许本客户端直接提交。
3. 保存仓库设置。令牌写入本机 SQLCipher，界面只显示“已保存”，不回填令牌；留空保留原令牌，可保存新令牌替换。设置未保存时禁止初始化或同步，避免使用旧目标。
4. 勾选同步范围后才能创建或接入：主机、文件夹、身份（包括密码和可导出私钥）、命令片段。服务器信任指纹、GitHub 令牌、平台解锁配置不随快照上传。仅本机排除已有核心规则，但界面尚未提供逐项开关；首版须接受所列整体范围。

保存设置后可点 **检查仓库与分支**，无需输入同步口令。检查只读取远端，并显示是否已有同步文件；不会生成密钥、上传数据或改变同步状态。读取成功不代表已验证 Contents 写入权限，仍需在 GitHub 令牌设置中确认。

### 新建时遇到 404

- **读取仓库信息失败：**核对仓库所有者/名称，以及 Fine-grained token 的 Resource owner、Repository access 是否包含这个私有仓库；组织仓库还需满足组织批准或适用的 SSO 授权要求。
- **读取同步分支失败：**核对分支名称及大小写，并确认令牌具有 Contents 读取权限。空仓库需先添加 README，形成首次提交和分支。
- 同步发布需要 Contents **Read and write**。在 GitHub 修改令牌权限后可直接重试；如果更换了令牌，在应用中保存新令牌再检查。新建空间的读取阶段失败不会创建同步批次，无需重置保险库。

GitHub 为避免泄露私有资源是否存在，权限不足也可能返回 404，因此不能仅凭状态码认定仓库不存在。依据：[GitHub 官方排错说明](https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api#404-not-found-for-an-existing-resource)。

## 创建和接入

- **第一台设备：创建同步空间。**输入独立同步口令（至少 12 字符），验证私有仓库后在本机生成随机同步密钥。此步骤不上传业务数据。离线保存界面显示的恢复码，再重新输入并勾选保存确认，通过实际恢复码解密核验后才能同步。
- 未确认的设置如果关闭窗口或退出应用，恢复码不会再次显示。可输入新同步口令重新生成恢复码，但只允许尚未确认、从未发布且没有待处理批次的空间；旧恢复码随之失效。保存了原码也可直接核验。
- **其他设备：使用同步口令或恢复码接入。**读取同提交的密钥信封和密文，成功解锁并认证数据后才原子安装本机同步状态。错误口令、损坏数据和写入失败均不留下半套设置。接入动作不覆盖业务数据，点击立即同步才合并。
- 创建或接入后固定仓库的数字 ID、名称和分支。首版不能直接更换仓库、解除绑定或在已接入设备更换同步密钥；避免手工删除数据库元数据。

## 手动同步与失败

- 点击 **立即同步**：核对已确认版本的祖先关系，认证解密远端快照，三方合并并原子保存批次，再发布两份加密文件；只拉取时确认远端版本。服务器指纹仍需逐台设备建立信任。
- 有待处理批次时按钮显示 **恢复待处理同步**：优先核对或完成原发布，不重新生成密文；如果在该批次后又编辑了数据，完成恢复后需再同步一次。
- 双端同项修改、修改/删除或身份引用问题会停止整次合并，保留本机和远端双方数据。现在可打开“处理同步冲突”，逐项选择本机/远端版本并确认；删除和身份依赖也会检查，详见 [冲突处理](SYNC_CONFLICTS.md)。
- 远端密钥信封变化会停止，不用旧密钥覆写远端。已有设备可通过“接入新同步密钥”接入，发起设备可通过“轮换 / 恢复同步密钥”管理轮换。
- 网络操作期间不能关闭设置窗口，可点击 **取消操作**。取消会结束当前网络 future 并保留已持久化状态；已经被 GitHub 接受的提交不能靠取消撤回，后续重试会读回核对。
- 保险库为网络操作临时借出数据库连接，锁定立即取消操作；旧任务释放连接时不能重新打开已锁定或新解锁的保险库。同步期间其他保险库读写返回忙碌，SSH 会话不占用该连接。
- 竞争发布、分叉、回退或历史超出 64 个提交核对上限时停止。竞争后的安全取消/重新合并尚待实现，因此不是所有错误都能通过重试自动恢复。禁止强制推送；REST 快进更新与外部管理员强推竞态见 [传输边界](SYNC_GITHUB.md)。

## 本机秘密与备份

`metadata.sync_account_v1` 存储仓库设置、令牌、仓库 ID 和恢复码确认状态，单项上限 16 KiB。使用同一 SQLCipher 主密码保护；令牌不加入同步快照，不通过 FFI 返回给 Flutter。同步口令、恢复码不以明文写入该记录；显示恢复码是新建时的一次性结果。Dart 字符串和第三方网络库内存副本不能保证清零。

完整加密数据库备份可能包含令牌和同步密钥，必须按敏感备份保管。应用“恢复为新记录”只导入业务记录，不复制这些同步元数据或替换当前绑定。没有后台自动同步，不在启动或打开设置时上传。

## 0.1.37：竞争后的恢复

若另一台设备抢先发布，点击“恢复待处理同步”会先核对旧发布结果。确定没有发布的普通批次会保留本机修改并重新合并；产生冲突时继续由用户选择。超时/响应丢失和旧版无法判断的记录不会被自动丢弃。详见 [竞争恢复及边界](SYNC_RECOVERY.md)。


## 0.1.38：接入另一台设备的新密钥

已初始化并完成恢复码核验后，可展开“接入新同步密钥”，输入新同步口令或恢复码。成功后点击“立即同步”才合并业务数据；有待处理发布时不能覆盖旧状态。详见 [换钥接入](SYNC_KEY_ADOPTION.md)。

## 0.1.39：本机发起或恢复密钥轮换

完成一次普通同步后，进入“轮换 / 恢复同步密钥”。依次输入两遍新同步口令、保存并重新输入新恢复码，核验通过后再点击“发布 / 恢复轮换”。只有读回远端确认成功，本机才启用新密钥。

关闭窗口不删除轮换。未发布的轮换可勾选确认后丢弃重建；发布结果不明时只允许恢复原批次。完整流程及边界见 [SYNC_ROTATION.md](SYNC_ROTATION.md)。

## 0.1.40：管理仅本机范围

创建/接入空间后、首次同步前，可以打开“管理仅本机范围”，选择主机、身份和片段。预览显示关联身份及共用身份主机的排除结果，确认后保存。取消不修改规则；已同步项不能直接撤回。详见 [SYNC_SCOPE.md](SYNC_SCOPE.md)。

## 0.1.41：断开 / 更换同步仓库

从此入口确认断开后，保留本机数据和仅本机规则，清除旧设置与本机同步密钥，可填写新仓库重新初始化。待处理发布、轮换与冲突会阻断；不会删除远端数据或撤销 GitHub 令牌授权。断开前请阅读密钥与备份边界，详见 [SYNC_DISCONNECT.md](SYNC_DISCONNECT.md)。
