## 一、范围与证据口径

- 对标的是用户能力和完整流程，不是照搬 React/Tauri 技术栈、界面素材、商业服务接口或源码。保留 Flutter + Rust。
- 官网文档描述不等于我们运行验证过 Cloud Term 产品；W Term 的“已有”也只表示当前工作树存在实现，真机验收另列。
- 同一页面的锚点、扩展名别名、更新日志中的重复修复不作为不同页面或不同功能重复计数。公开页面覆盖和逐项来源见后文清单。
- 用户登录后的控制台、第三方服务、二进制安装包、静态资源不属于公开页面全文验证。遇到访问失败必须记录，不声称抓取了不可访问内容。
- 彩蛋小游戏、游戏成绩与排行榜排除。账号、通知、搜索等正常产品功能不能因也被游戏使用而一起排除。
- 原 W Term 目标中已有但官网未证实的能力另列，不冒充 Cloud Term 已有功能。官网明确尚未提供的供应商也只列预留项。
- 当前 SFTP 新功能继续暂停。**P5是恢复扩展的候选位置，不是自动解除暂停的许可**；P1–P4只修复影响使用/数据安全的缺陷，到达P5前再次确认用户是否恢复，未确认则跳过增强、继续其他已授权方向。

## 二、目标平台与适配方式

| 能力 | macOS / Windows | iPhone / iPad | Web |
| --- | --- | --- | --- |
| SSH、SFTP、身份、同步 | Rust 原生核心、完整键鼠入口 | 相同协议与数据；触摸、辅助键、文件授权适配 | P12 独立方案；浏览器不能直接使用现有原生 FFI/TCP |
| 多窗格/广播/工作区 | 多窗格、多窗口、显式广播目标 | iPad 可多窗格；iPhone 用会话切换/工作区摘要，避免硬塞桌面布局 | 在网关与会话授权完成后接入 |
| 本地 Shell/PowerShell | macOS PTY、Windows ConPTY；与远端会话清楚区分 | 不承诺突破系统沙盒的本机 Shell | 不把服务端 Shell 伪装成访问者本机 Shell |
| 托盘/菜单栏/资源管理器/外部编辑器 | 原生适配、可关闭、权限最小化 | 用系统分享/文件选择/通知替代；无意义功能隐藏并说明 | 受浏览器剪贴板、下载、通知权限限制 |
| 串口/RDP | 串口按系统权限；RDP 首版调用已安装系统/用户客户端 | 硬件/系统能力单独评估，不显示不可用连接为“已支持” | 没有网关或受支持浏览器能力时不承诺等价 |
| 运维监控/Docker/tmux/Redis | 共享 Rust 服务与模型 | 提供精简但可完成流程的页面 | 依赖受控网关和权限模型 |
| AI、插件、同步、组织 | 共同授权和数据边界 | 不降低凭证保护，遵守后台限制 | 账号安全与本地密钥存储独立设计 |

默认顺序仍为 **Apple 核心验收 → Windows 核心 → 高级能力 → Web → Android 最后评估**。macOS Intel、Windows ARM64 等兼容扩展先列验证任务，不从对标产品的下载列表推导本项目已经支持；Linux 不列入本轮承诺。Android 如决定实施，再立独立阶段和设备验收矩阵。

### P1：先完成当前断点

1. **路线数据与依赖**：已保存主机/身份引用、顺序、长度上限、自引用/循环/缺失检测；删除、复制、导入、恢复、同步的引用闭包一起处理。
2. **逐跳连接**：全局/主机代理只作用于第一跳；后续用上一跳的 `direct-tcpip` 通道建立下一跳 SSH；每跳展示目标、确认指纹、认证/MFA；不拼接本地 `ssh`/ProxyCommand。
3. **信任域**：当前 `host:port` 不能直接推广为不同路线的同名内网服务器；设计稳定的路线信任上下文和迁移，不能自动批准旧记录与新目标的等同关系。
4. **资源与取消**：开始探测前返回/建立可取消操作标识；整条链只有清楚的资源拥有者。取消、超时、上游断开、保险库锁定、iOS 后台都关闭父连接/子通道/等待问题/转发。
5. **连接策略**：保存纯交互式认证模式；命名代理与逐主机选择/继承、代理测试，区分“代理 TCP 可达”“认证成功”“能访问目标”。凭证不回填，修改端点不得复用旧密码。
6. **三类转发**：远程监听审批/取消和动态 SOCKS 协商；保存规则和会话启停分开。默认 loopback，暴露公网/局域网显式警告；规则保存不等于自动监听。
7. **验证**：至少两层跳板加目标、逐跳错指纹/错密码/MFA/取消、上游中断、代理失败不直连、端口冲突/远端拒绝、断开后整链资源释放；真实 Dart/Rust 桥接与 Apple 包内核验。

P1 按“多跳 → 认证/代理缺口 → 远程转发 → 动态转发 → 规则持久化”拆交付，不一次性积累所有改动再验证。

### P6–P9：运维、协议、插件与 AI

- **采集**：独立 SSH exec/SFTP 通道、不占用交互 Shell；Linux/OpenSSH优先，NAS/Windows 等能力探测后降级。刷新频率/输出大小/缓存 TTL 有界，后台/不可见时暂停。
- **进程/端口/磁盘**：权限不足不是空数据；监听端口不等于公网可达，延迟不承诺 ICMP ping。`du`等耗时任务按需授权、可取消、显示缓存时间；结束进程/删除容器等操作独立确认。
- **Docker/tmux**：先列表、状态、日志与会话附着，再启停/重命名/删除；不自动安装 Docker/tmux，不静默 sudo。tmux 保活≠本地SSH连接永不掉线。
- **Telnet/串口/RDP**：Telnet明确明文风险且不复用SSH密码；串口处理设备选择/波特率等参数和热拔插；RDP调用受支持客户端并检测是否安装，凭证不放命令行或长期明文临时文件。
- **Redis**：单机 → SSH跳板 → ACL/TLS → 哨兵/集群 → 拓扑/凭证 → 数据操作/REPL；大键分页/限量，破坏性命令额外确认，集群重定向和发现地址不得绕开配置的路由。
- **命令上下文**：Shell 集成、OSC 7/133、cwd和命令结束事件统一处理；远端上报是不可信数据，不可直接触发写操作。修改 shell 配置需预览、授权和可逆恢复，不默改启动文件。
- **插件**：实现内置且可关闭的命令补全、文件预览、IP归属、JSON格式化、任务通知，声明网络/文件/终端权限与资源预算。官网未证实第三方插件SDK/安装市场，不把开放任意代码扩展算作对标必需；未来确有需求再独立设计包签名、沙箱和兼容机制。
- **IP/通知/分享**：0.3.5发布说明已从指南中的ipapi.co改为对方自有服务上的离线IPv4库，只列国家/省市/运营商，不再承诺ASN/时区/经纬度。W Term优先评估许可明确的本机库；若用服务端查询，仍会发送待查IP，须按需告知，内网/回环不外传。通知/图片分享/日志默认隐藏可能敏感的主机和正文，导出前预览。任务完成检测区分可靠协议与启发式结果，不把提示符猜测称为准确退出码。
- **资源目录与离线包**：P8先完成原创本地主题/鼠标包的预览、校验、原子安装、失败保持当前状态和离线恢复，再接可选公共目录。包有格式版本、大小/解码像素上限、路径/外链校验；SVG禁脚本与远程加载，鼠标检查七状态、热点及回退。摘要只证明内容与目录相符，不等于来源可信或获得再分发许可；不默认请求/镜像对方API。对方.cttheme内部格式本轮未取得，不承诺兼容；本项目先定义自己的数据格式。P10再接明确授权的完整快照同步；本机下载目录不随外观设置上传。
- **AI**：先只读问答/生成待确认命令，再受控执行。支持多供应商和模型、显式上下文范围、脱敏预览、历史清除、超时取消；密钥只存安全凭证层，不落普通配置或浏览器明文存储。

- Gist不是私有仓库：所谓secret Gist不提供仓库式私有访问控制，必须依赖E2EE、清楚提示可见性，另行证明并发与恢复语义。官方云、自托管服务和GitHub分别有适配与一致性测试，凭证按后端隔离。

- 组织按成员/角色/集合授权，连接/片段/凭证、公钥目录、密钥分发、同步回滚和审计均列正式目标。需要独立组织密钥生命周期、设备加入/撤销、租户隔离与服务端操作版本校验，不能只在客户端隐藏按钮。
- “用户能使用凭证但看不到凭证”不能仅靠遮蔽UI兑现：原生客户端持有可解密秘密时有内存可见性；真正不下发秘密的场景需要网关、短期证书或服务端签名器，必须另列信任边界。
- 成员移除/密钥轮换只能保护之后的访问，无法撤回已下载历史或旧凭证；根据泄露面决定远端密码/密钥撤销，不以删成员代替服务器侧撤权。
- 组织订阅、兑换码、套餐/配额、客服反馈跟踪可在运营阶段实现；支付渠道、托管成本、条款和账号资质是上线依赖，不让开发客户端即默认产生费用或外部资源。

## 四、数据与架构联动规则

1. **既有模型新增字段**：HostProfile序列化/复制/编辑/导入 ↔ Rust Host `deny_unknown_fields`校验 ↔ 同步校验 ↔ 备份恢复/ID重映射同时修改。新旧客户端能力协商/最低格式版本明确；旧版不能理解的新格式拒绝写入，不能默默丢字段。
2. **新增实体**：命名代理、转发规则、工作区、连接协议、片段参数等先定义本机/可同步范围，再处理schema、稳定ID、引用闭包、删除/恢复、冲突中心、容量限制；数据库全量导出不代表恢复函数自动支持新实体。
3. **不自动同步的东西**：运行连接/进程ID、文件授权/本机路径、窗口坐标、服务器信任批准、AI API key、供应商令牌、监控缓存、命令历史和编辑草稿。确有跨设备需求时单独设计授权、加密和保留策略。
4. **会话所有权**：连接资源归会话服务，页面只是视图；多窗口、SFTP、监控、转发、AI各持有明确租约/引用。退出/锁定/上游失败由统一生命周期关闭，不因移动Widget造成失联或泄漏。
5. **协议与平台**：Rust继续持有网络、任务和秘密；Flutter只编排界面和授权。PTY/ConPTY/生物识别/文件授权用原生适配，Web另设边界，不复制一套不一致的SSH认证逻辑。
6. **桥接**：修改Rust公开API后运行固定FRB 2.13.0生成器，更新adapter和测试，不手改生成文件。新增Rust文件必须进入构建hook依赖，顺序构建，不并发改源码和打包。
7. **导入安全**：配置、插件、主题、压缩包、远端输出都是不可信输入。做大小/路径/格式/引用校验，不能让导入配置自动执行命令、批准指纹或开启公网监听。
