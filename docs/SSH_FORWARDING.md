# 端口转发：本地 -L、远程 -R 与动态 SOCKS5 -D

更新：2026-10-28，0.1.46 (47)。macOS/iOS 共用 Rust 转发核心；这是 P1-C 会话级转发与设备本地保存规则，不含 Web 网关转发或 UDP。

## 使用

在已连接会话顶部点击“端口转发”。对话框包含当前会话的转发和保存的规则。

### 本地 -L

- 在**本机**监听，目标由 **SSH 服务器**连接。适合访问服务器所在内网的服务。
- 默认监听 `127.0.0.1`，仅本机可用；`0` 表示自动分配监听端口。
- 示例：本机 `127.0.0.1:8080` → 服务器侧 `db.internal:5432`。

### 远程 -R

- 在 **SSH 服务器**上监听，目标由**本机**连接。适合把本机服务临时暴露给服务器。
- 默认请求服务器回环 `127.0.0.1`；是否允许 `0.0.0.0`/局域网取决于服务器 `GatewayPorts` 等策略，失败会显示服务器拒绝。
- 监听位置在“当前会话转发”中明确标记为“远端”；停止时同时通知服务器取消监听并释放本地中继。
- 示例：服务器 `127.0.0.1:9000` → 本机 `127.0.0.1:3000`。

### 动态 SOCKS5 -D

- 在**本机**启动无认证 SOCKS5 监听，客户端自行选择目标，经当前 SSH 连接转发。仅支持 SOCKS5 CONNECT / TCP；不包含 UDP、BIND 或 VPN。
- 默认监听 `127.0.0.1`，仅本机应用可使用；监听非回环地址时会显示风险提示。任何能访问该端口的设备都可以使用此代理，不提供 SOCKS 用户名/密码认证。
- 这不是“连接代理”：连接代理用于本应用向外建立 SSH 连接，动态转发的 SOCKS5 入口是给其他本机程序使用的。

## 保存规则与手动启停

- 有已保存主机的会话可以填写规则名称并“保存规则”。规则按主机保存在**本机** SQLCipher 元数据中，不进入 GitHub 同步，也不由业务备份恢复导入。
- 保存规则**不会自动启动**；需要在“保存的规则”中手动点击启动。编辑、搜索、删除规则；删除运行中的规则不会自动停止对应转发，需要单独停止。
- 规则类型、监听地址/端口、目标地址/端口在本机校验；每台主机同名规则拒绝。最多 64 条规则；每会话最多 8 条活动转发，每条最多 32 个并发连接。
- 断开会话、关闭工作区、锁库或 SSH 上游中断会停止全部会话级转发；规则本身保留，下一次连接后可手动启动。

## 安全与边界

- 默认只监听回环；非回环监听必须勾选“我确认允许外部访问/其他设备使用”后才能启动或保存规则，启动已保存的非回环规则时会再次确认。远端 -R 还受服务器配置限制，动态 -D 等于向能访问该端口的设备提供无认证代理。
- 本地/动态转发不向 SSH 客户端暴露服务器；远程转发的连接由服务器回传为 `forwarded-tcpip` 通道，再由本机连接目标。服务端可看到目标地址。
- 代理/转发失败只报错，不回退直连；目标连接超时 15 秒；连接错误显示在对应活动转发上。停止、断链或取消会释放监听、活动中继和远端监听。
- 动态 SOCKS5 的客户端流量与 SSH 传输共用当前已认证会话；不会重新进行 SSH 认证，也不会把 SSH 凭证交给 SOCKS 客户端。
- 尚未实现：Web 网关监听位置、UDP、SOCKS 认证、自动启动/保活、跨设备规则同步、ZMODEM/rz/sz（属 P5 暂停范围）。
