# 断开与更换同步仓库

更新：2026-10-08，0.1.41 (42)。入口：GitHub 同步 → 断开 / 更换同步仓库。

## 操作

1. 查看旧仓库及分支，确认是否需要保留恢复凭证和加密备份。
2. 勾选已保存所需凭证和备份、理解本机旧同步密钥将移除，然后输入“断开”。
3. 点击确认断开。成功后原设置与临时凭证输入清空，允许填写新的仓库、分支及令牌。
4. 保存新设置，再创建新空间或使用其现有同步口令/恢复码接入。随后手动同步会合并本机现有记录，并执行仅本机规则。

仅保存过仓库设置、尚未初始化时也可断开。取消窗口不写入；提交期间不能重复确认或关闭。失败后须重新读取信息并重新确认。设置尚有未保存修改时入口禁用。

## 保留与移除

保留主机、身份、密码/私钥、片段、文件夹、服务器指纹及其他保险库记录。保留仅本机范围，并把当时依赖闭包中的关联身份/主机一起记为本机规则，避免更换空间后因旧检查点移除而失去关联保护。重新接入后可以在范围管理中逐项调整。

移除本机 GitHub 令牌、仓库绑定、同步检查点/回执、当前同步密钥和同步密钥历史。操作完全在本机 SQLCipher 事务内完成，不访问或修改 GitHub，不撤销令牌在 GitHub 的授权，不删除远端历史或其他设备的数据。

重新接入旧空间需要它当前的同步口令或恢复码。当前恢复码不能恢复过去轮换的全部旧密钥。加密备份包含当时的 metadata，可保留这些资料，但现有“恢复为新记录”界面不会自动恢复同步密钥历史；没有完整历史密钥恢复工具。需要旧历史时，应在断开前保留完整加密备份及备份口令。

## 阻断与原子性

- 任何待处理同步、发件箱、发布日志、轮换候选或冲突审阅都禁止断开，包含从旧版本留下的记录。请先走原恢复/冲突/安全丢弃轮换流程；无强制清理未知发布的入口。
- 同步元数据损坏、超限或未知新版本记录拒绝断开，不尝试模糊匹配批量删除。
- 预览版本绑定同步记录和当前业务快照。仓库、凭证、主机关联或同步状态变化后，旧确认不能执行。
- 在同一写事务中重新检查、保存仅本机规则并删除明确列出的旧同步元数据；任一步失败全部回滚。

新增 `sync_local_policy_v1` 独立本机元数据，不加入远端协议。旧保险库无需预迁移：修改范围、断开或重新生成未发布恢复码时保留已有规则，新初始化时读取规则。创建空间后重新生成未核验恢复码也不会清空范围。建议所有设备使用当前版本，旧应用不具备此保留逻辑。
