# 跳板路线（多级 SSH）

更新：2026-10-28，0.1.45 (46)。macOS/iOS 共用 Rust SSH 核心；本文件描述 P1-A 多级跳板。P1-B 的持久交互式身份、命名/逐主机代理与分层测试见 [SSH_PROXY.md](SSH_PROXY.md) 和 [SSH_INTERACTIVE_AUTH.md](SSH_INTERACTIVE_AUTH.md)；远程/动态转发（P1-C）尚未实现。

## 使用方式

1. 先保存要作为跳板的主机，并为它配置加密保存的身份/私钥。跳板主机必须使用已保存身份，不能在连接时临时输入密码。
2. 编辑目标主机，在「跳板路线」中选择已保存主机。列表顺序即连接顺序：第 1 项是第一跳，最后才是目标主机；最多 4 台跳板（含目标最多 5 个 SSH 连接）。
3. 双击目标主机。界面逐跳显示进度：建立连接 → 核对/首次确认指纹 → 认证（含 MFA）→ 下一跳。全部完成后打开目标终端。
4. 断开目标终端、关闭工作区、锁定保险库或取消连接都会释放整条链。

跳板主机自身也可以有跳板路线；连接目标时会先展开它的路线。路线存在缺失引用、重复主机、循环或超过 4 台跳板时，连接在建立任何网络连接前失败并显示原因。

## 网络与信任边界

- **代理只作用于第一跳。** 第一跳使用该跳主机的代理设置（继承默认 / 直连 / 指定命名代理）；后续跳通过上一跳已认证传输上的 `direct-tcpip` 通道建立，目标地址由上一跳服务器解析。不会拼接或执行本地 `ssh`/`ProxyCommand`。
- **失败不回退直连。** 通道被拒绝、上游断开或目标不可达时直接报错；不会绕过跳板尝试直连目标。
- **逐跳指纹。** 每一跳独立核对服务器 SHA256 指纹；在指纹获准前不发送密码或私钥签名。新增或变化的指纹会阻断认证。
- **路线隔离的信任键。** 第一跳沿用原来的 `host:port` 信任键；后续跳使用 `跳板1 > 跳板2 > 目标` 形式的键。同一内网地址经不同路线（或直连）访问是不同信任上下文，不会复用旧批准，也不会自动把旧的直连信任推广到跳板路线。
- **认证。** 跳板跳只完成 SSH 认证，不申请 PTY/Shell；只有目标跳建立终端。每跳都可进行服务器要求的多轮 keyboard-interactive/MFA，问题仍绑定该连接和一次性轮次。

## 取消与资源所有权

- 连接尝试有独立的操作标识；在 SSH 握手/代理隧道/跳板通道建立阶段可立即取消，不必等待 20 秒超时。
- 每个已认证连接记录其父连接。断开任一跳会同时清理它的上游与下游，避免遗留已认证跳板或悬空终端。
- 探测中的连接 120 秒未获指纹批准会整体清理；保险库锁定、iOS 后台断开和工作区销毁同样关闭整条链。
- 服务端 keepalive 20 秒、最多 3 次；上游真正断线后子传输会结束，界面仍按现有策略提示断线，不自动重连或重放命令。

## 数据与兼容

- 主机 JSON 新增可选字段 `jumpHostIds: string[]`；无此字段的旧数据按空路线读取。
- Rust 在写入、备份恢复、删除文件夹和同步合并时校验：每台最多 4 个直接跳板、不能自引用或重复、引用必须存在、整张主机图不超过 4 层跳板且无循环。
- 删除仍被其他主机引用的跳板会被阻止；界面会列出依赖主机。删除文件夹时同样阻止删除这些主机。
- 加密备份恢复会为目标主机生成新 ID，并把 `jumpHostIds` 重映射到同一备份内的新 ID；引用不在备份内时拒绝恢复。
- 同步：
  - 跳板主机设为「仅本机」会同时把依赖它的主机排除出同步，避免对端收到断链路线。
  - 远端删除跳板主机、同时本机仍保留引用它的主机时，同步进入冲突审阅，需要同时保留跳板或选择不使用它的主机版本；无法修复的悬空引用会阻止写入。
  - 旧版 W Term 使用 `deny_unknown_fields`，遇到 `jumpHostIds` 会拒绝写入/恢复，而不是静默丢弃路线；升级前请先升级所有设备。
- 路线只保存主机引用，不复制密码/私钥；跳板身份仍通过保险库身份表解析，不使用明文回填。

## 当前限制

- 跳板必须使用已保存身份；身份可以是密码、私钥或“仅交互式”；尚未提供逐跳临时凭证输入。
- 代理只用于第一跳；命名代理与主机绑定是设备本地数据，不跨设备同步。命名代理缺失时拒绝连接，不回退直连。
- 尚无多跳的持久自动重连、布局恢复和转发规则自动启动。
- 真实 OpenSSH 多跳、PAM/TOTP、弱网和签名真机验收仍需单独记录；隔离 fixture 通过不等于真实环境验收。

## 验证

- Rust 单元测试覆盖路线字段/长度/循环/缺失引用、删除保护、备份重映射、同步悬空引用阻止和仅本机依赖排除。
- 隔离 fixture 启动三台 SSH 服务器；Rust 协议测试直接使用 A→B 双跳，真实 Dart/Rust 桥接使用 A→B→C（两台跳板加目标）。覆盖第二跳错误指纹阻断、跳板错误密码、断开父连接级联清理、跳板拒绝时不回退直连、握手阶段即时取消、跳板 MFA 不创建终端。
- 真实 Dart/Rust 动态库桥接覆盖：取消进行中的握手、三层终端往返、逐跳错误密码、缺失父连接失败、断开第一跳后后续跳失效、保险库锁定后拒绝新跳板连接。
- 2026-10-28 结果：118 项普通 Rust、15 项 fixture、5 项真实 SSH 桥接（转发、MFA×2、代理、三层跳板路线）、1 项真实保险库桥接、188 项 Flutter 测试通过；Rust 格式/Clippy 与 Flutter 静态检查通过。真实 OpenSSH 多跳、PAM/TOTP、弱网与签名真机仍待验收。
