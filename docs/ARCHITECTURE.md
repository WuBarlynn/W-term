# Vertical prototype architecture

## Trust and connection state

`probe_server` performs key exchange, captures the SHA256 host fingerprint and keeps the unauthenticated transport for at most 120 seconds. The Flutter trust store reads the OS Keychain. New fingerprints require explicit confirmation; changed fingerprints fail closed. `authenticate` checks the approved fingerprint against the **same transport**, then sends credentials. Rekey must retain the original server key. Private credentials are not part of any persistent UI model.

Pending, authenticating and connected states are kept in Rust. Authentication has a deadline and a cancellation channel; disconnect is idempotent. Terminal output is a bounded Rust queue and a one-frame/ACK FFI stream. UTF-8 decoding is incremental in Dart. The final output is drained before stream closure. A slow/unresponsive consumer is disconnected after the ACK deadline. No command is automatically replayed.

The terminal and SFTP use separate channels on one authenticated transport. SFTP is initialized lazily. Upload/download operations stream through Tokio, rather than bridging entire files. Downloads go to a new local temporary file. Uploads use a random exclusive remote temporary file and an SFTP v3 no-replace rename. Existing destinations are rejected. There is no recursive operation, resume or overwrite workflow in this milestone.

## Layer boundaries

- `lib/app`: workspace/session navigation and Keychain host trust.
- `lib/features`: connection form, terminal adapter and files UI.
- `rust/src/api`: stable typed interface generated by flutter_rust_bridge.
- `rust/src/session.rs`: transport/authentication/channel ownership and cancellation.
- `hook/build.dart`: native-assets compilation and bundling of the shared core.
- `tests/fixtures`: disposable SSH/SFTP interoperability environment.

No shell command interpolation is used for file operations. Remote filenames are never joined directly into a local filesystem path. Application-level diagnostics do not include secrets or terminal content.

## Platform behavior

Desktop layout uses a host sidebar, top session tabs and optional SFTP panel. Compact layouts use a host drawer and session tabs and full-screen terminal/files with an auxiliary keyboard. iOS backgrounding closes the transport in this milestone; returning to the app does not replay or reconnect. Platform-specific file access remains in Flutter/native plugins; the Rust core only accesses app-owned staging files.

## Vault and profiles

`VaultGate` owns the unlocked workspace lifetime. `NativeVaultSession` implements `HostStore` / `FolderStore` through the generated bridge. `rust/src/api/vault.rs` owns SQLCipher, schema validation, migration and the token-protected database handle. The platform supplies only its application-support path; this storage core has no Apple-specific API.

`HostProfile` contains ID, name, endpoint, username, group, tags and favorite state. Only an identity reference is present; credential secrets and fingerprints are absent. `KeychainHostStore` is retained as the read source for legacy migration and tests; production writes use the vault. See [VAULT.md](VAULT.md) for encryption, migration and locking details.

The encrypted identities table now supports credential reuse, native authentication, password rotation and encrypted backup export/import. Next: generated keys, recovery codes, quick unlock and the sync envelope before GitHub synchronization. Windows and Android scaffolds remain absent.

## Workspace layout

The embedded `HostsPage` owns the left host tree; compact layouts expose it in a drawer. A shared widget key preserves the panel state across layout changes. Existing `HostProfile.group` values map directly to folder names. Explicit empty folders use the `FolderStore` interface and a separate encrypted record in the same SQLCipher database. Double-clicking a host uses its saved identity and the unchanged fingerprint verification flow. An old profile without credentials first opens the profile editor. Sessions are independent, compact tabs above the right workspace; closing an earlier tab preserves the active session by identity.

Nested folders use normalized UI paths. `vault_delete_folder` updates folders and host membership in one transaction. `vault_save_host` validates identity references and atomically saves an optional new credential with its host; credentials do not return through FFI. `vault_restore_backup` creates new record IDs and remaps references while preserving destination records.
